# FUNDAMICS LMS Backend — API Specification (V1.4)

This document contains the exhaustive, verified REST API specification for all 37 endpoints implemented in the FUNDAMICS LMS backend.

---

## Standard Response & Error Envelope

All API errors generated by application logic return a uniform JSON format:

```json
{
  "success": false,
  "error": {
    "code": "ERROR_CODE_STRING",
    "message": "Human readable error description",
    "details": null
  },
  "request_id": "req_84f9b201dc4e"
}
```

### Standard Status Codes
- `200 OK`: Request succeeded.
- `201 Created`: Resource successfully created.
- `400 Bad Request`: General domain or constraint violation (`BAD_REQUEST`).
- `401 Unauthorized`: Missing, expired, or invalid credentials (`UNAUTHORIZED`).
- `403 Forbidden`: Authenticated user lacks required role permissions (`FORBIDDEN`).
- `404 Not Found`: Target entity does not exist (`NOT_FOUND`).
- `409 Conflict`: Unique constraint violation or duplicate submission (`CONFLICT`).
- `422 Unprocessable Entity`: Input payload validation failure (`VALIDATION_ERROR`).
- `429 Too Many Requests`: Rate limit exceeded (`RATE_LIMITED`).

## 1. System & Health Endpoints

### GET `/`
- **Purpose:** Root greeting and documentation URL pointer.
- **Handler:** `src.main.root`
- **Authentication:** Public
- **Response `200 OK`:**
  ```json
  {
    "message": "Welcome to FUNDAMICS LMS API",
    "docs": "/api/v1/docs",
    "version": "1.4.0"
  }
  ```

### GET `/api/v1/health/live`
- **Purpose:** Kubernetes / Docker liveness probe to verify the application process is up.
- **Handler:** `src.api.v1.health.liveness_probe`
- **Authentication:** Public
- **Response `200 OK`:**
  ```json
  {
    "status": "ok",
    "app": "FUNDAMICS LMS API"
  }
  ```

### GET `/api/v1/health/ready`
- **Purpose:** Readiness probe that tests live database connectivity (`SELECT 1`).
- **Handler:** `src.api.v1.health.readiness_probe`
- **Authentication:** Public
- **Response `200 OK`:**
  ```json
  {
    "status": "ready",
    "database": "ok",
    "version": "1.4.0"
  }
  ```
- **Error Response `200 OK` (Degraded):**
  ```json
  {
    "status": "not_ready",
    "database": "unavailable: <connection error details>",
    "version": "1.4.0"
  }
  ```

### GET `/api/v1/version`
- **Purpose:** Retrieves application name, version, runtime environment, and timezone.
- **Handler:** `src.api.v1.health.version_info`
- **Authentication:** Public
- **Response `200 OK`:**

  ```json
  {
    "name": "FUNDAMICS LMS API",
  ```

## 2. Authentication & Profile Endpoints

### POST `/api/v1/auth/login`
- **Purpose:** Authenticates user credentials, writes an audit record, and issues access and refresh tokens.
- **Handler:** `src.api.v1.auth.login`
- **Authentication:** Public
- **Request Body (JSON):**
  ```json
  {
    "email": "admin@fundamics.com",
    "password": "SecurePassword123!",
    "device_info": "Chrome / macOS"
  }
  ```
- **Response `200 OK`:**
  ```json
  {
    "access_token": "eyJhbGciOi...",
    "refresh_token": "48_char_url_safe_token",
    "token_type": "bearer",
    "expires_in_seconds": 900
  }
  ```
- **Errors:** `401 Unauthorized` if credentials are invalid or user status != ACTIVE.

### POST `/api/v1/auth/refresh`
- **Purpose:** Rotates refresh token (revokes current session and mints a new one) and issues a new access token.
- **Handler:** `src.api.v1.auth.refresh`
- **Authentication:** Public
- **Request Body (JSON):**
  ```json
  {
    "refresh_token": "48_char_url_safe_token"
  }
  ```
- **Response `200 OK`:**
  ```json
  {
    "access_token": "eyJhbGciOi...",
    "refresh_token": "new_48_char_url_safe_token",
    "token_type": "bearer",
    "expires_in_seconds": 900
  }
  ```
- **Errors:** `401 Unauthorized` if refresh token is expired, revoked, or non-existent.

### GET `/api/v1/auth/me`
- **Purpose:** Retrieves authenticated user's profile details including linked student/teacher IDs and codes.
- **Handler:** `src.api.v1.auth.get_me`
- **Authentication:** Bearer JWT (Any authenticated role: `ADMIN`, `TEACHER`, `STUDENT`)
- **Response `200 OK`:**
  ```json
  {
    "id": "c1f7a63e-2b5d-4f38-9441-2a623048995a",
    "name": "Jane Doe",
    "email": "jane@example.com",
    "phone": "+919876543210",
    "role": "STUDENT",
    "status": "ACTIVE",
    "student_id": "6a30c5e7-...",
    "teacher_id": null,
    "student_code": "STU-2026-001",
    "teacher_code": null
  }
  ```

### POST `/api/v1/auth/logout`
- **Purpose:** Revokes user's active session.
- **Handler:** `src.api.v1.auth.logout`
- **Authentication:** Bearer JWT
- **Response `200 OK`:**
  ```json
  {
    "success": true,
    "message": "Logged out successfully"
  }
  ```

## 5. Admin — Student Attendance

### POST `/api/v1/admin/attendance/preview`
- **Purpose:** Stage 1 validation of student attendance entries. Verifies student codes against active class/batch enrollments and checks for existing attendance records on that date.
- **Handler:** `src.api.v1.attendance.preview_attendance_import`
- **Authentication:** Bearer JWT (Requires `ADMIN` role)
- **Content-Type:** `multipart/form-data` or `application/x-www-form-urlencoded`
- **Form Fields:**
  - `class_id` (UUID)
  - `batch_id` (UUID)
  - `attendance_date` (Date string: `YYYY-MM-DD`)
  - `records` (List of JSON-serialized `AttendanceRecordInput`: `student_code`, `status`, `remarks`)
- **Response `200 OK`:**
  ```json
  {
    "import_id": "a98811d7-f495-46aa-b2b7-832813136277",
    "filename": "manual_staged_import.json",
    "class_id": "4168c481-...",
    "batch_id": "8c41ec35-...",
    "attendance_date": "2026-10-01",
    "total_rows": 25,
    "valid_rows": 25,
    "error_rows": 0,
    "preview_data": [
      {
        "row_number": 1,
        "student_code": "FND-2026-101",
        "student_name": "Rohan Sharma",
        "status": "PRESENT",
        "is_valid": true,
        "error_message": null
      }
    ]
  }
  ```

### POST `/api/v1/admin/attendance/confirm/{import_id}`
- **Purpose:** Stage 2 atomic commit of validated student attendance records.
- **Handler:** `src.api.v1.attendance.confirm_attendance_import`
- **Authentication:** Bearer JWT (Requires `ADMIN` role)
- **Path Parameters:** `import_id` (UUID)
- **Request Body (JSON):**
  ```json
  [
    {
      "student_code": "FND-2026-101",
      "status": "PRESENT",
      "remarks": "On time"
    }
  ]
  ```
- **Response `200 OK`:**
  ```json
  {
    "import_id": "a98811d7-f495-46aa-b2b7-832813136277",
    "status": "COMPLETED",
    "committed_rows": 25,
    "message": "Successfully committed 25 student attendance records"
  }
  ```
- **Errors:** `404 Not Found` if import record does not exist; `409 Conflict` if import session is already `COMPLETED`.

## 12. Integrations — External Webhook

### POST `/api/v1/integrations/biometric/secureye/events`
- **Purpose:** Webhook ingestion endpoint for Secureye biometric time-and-attendance devices.
- **Handler:** `src.api.v1.biometric.ingest_biometric_events`
- **Authentication:** Custom Header `x-device-secret` (must match active `BiometricDevice.secret_reference`)
- **Request Body (JSON):**
  ```json
  [
    {
      "device_id": "DEV-MUM-01",
      "external_event_id": "EVT-90023184",
      "employee_identifier": "SEC-EMP-0042",
      "event_type": "IN",
      "event_at_utc": "2026-10-01T08:31:00Z"
    }
  ]
  ```
- **Response `200 OK`:**
  ```json
  {
    "processed": 1,
    "duplicates_skipped": 0,
    "unmapped_employees": 0,
    "message": "Ingested 1 biometric events (0 duplicates skipped)"
  }
  ```
- **Errors:** `401 Unauthorized` if `x-device-secret` does not match an active registered device.
